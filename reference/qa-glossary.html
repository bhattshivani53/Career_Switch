QA Glossary

Quick reference — every term you need for a Junior QA interview.

Core Concepts

Quality Assurance (QA)
Process-focused, proactive. Sets standards and processes to prevent defects from occurring.
Quality Control (QC)
Product-focused, reactive. Checks outputs against standards to detect defects.
Testing
A specific QC activity: executing software to find defects.
Defect / Bug
A deviation between actual and expected software behaviour.
Verification
"Are we building the product right?" — checking against specifications.
Validation
"Are we building the right product?" — checking against user needs.

SDLC & STLC

SDLC
Software Development Lifecycle — the end-to-end process of building software: Requirements → Design → Dev → Test → Deploy → Maintain.
STLC
Software Testing Lifecycle — QA's own process within SDLC: Requirement Analysis → Test Planning → Test Case Dev → Env Setup → Execution → Closure.
UAT
User Acceptance Testing — final testing by business users before release.
Shift-Left
Testing earlier in the SDLC to catch defects before they become expensive to fix.

Testing Types

Functional Testing
Does the software do what it should? Checks behaviour against requirements.
Non-Functional Testing
Does it do it well enough? Covers performance, security, usability, accessibility.
Smoke Testing
Broad, shallow — "is the build alive?" Quick check of critical paths after a new build.
Sanity Testing
Narrow, deep — checks a specific fix works and hasn't broken related functionality.
Regression Testing
Re-testing existing features after a code change to ensure nothing broke.
Exploratory Testing
Unscripted testing guided by tester intuition and curiosity to find unexpected bugs.
Re-testing
Re-running the exact steps of a bug after it's been fixed to confirm the fix works.

Test Design

Equivalence Partitioning (EP)
Divides inputs into groups that behave the same. Test one value per group.
Boundary Value Analysis (BVA)
Tests values at, just below, and just above the boundaries of valid input ranges.
Decision Table
Maps all combinations of conditions to expected outcomes. Ensures full combination coverage.
State Transition
Tests valid and invalid transitions between system states.
Error Guessing
Using experience to target where bugs are most likely — empty fields, boundaries, special chars.
Positive Testing
Tests the happy path — valid inputs, expected user behaviour.
Negative Testing
Tests what happens with invalid inputs or unexpected user behaviour.

Test Artifacts

Test Plan
Document describing scope, approach, resources, timeline, and risks for a testing effort.
Test Case
Documented steps with preconditions, test data, and expected result to verify one behaviour.
Test Suite
A collection of related test cases.
Test Execution Log
Record of which tests were run, when, and what results were observed.
Bug Report / Defect Report
Documentation of a defect: steps to reproduce, actual vs expected result, severity, priority.
Test Summary Report
End-of-cycle document summarising what was tested, pass/fail counts, and outstanding issues.

Bug Life Cycle

New
Bug just reported, not yet reviewed.
Assigned
Bug confirmed and assigned to a developer.
Open / In Progress
Developer is working on the fix.
Fixed / Resolved
Developer believes the bug is fixed. Ready for QA re-test.
Retest
QA is re-testing the fix.
Closed
Fix verified — bug no longer exists.
Reopened
Fix didn't work — bug exists again.
Rejected / Not a Bug
Developer/PM confirms this is expected behaviour, not a defect.
Deferred
Valid bug but won't be fixed in this release.
Severity
How bad the impact of the bug is (Critical, Major, Minor, Trivial).
Priority
How urgently the bug needs to be fixed (High, Medium, Low) — a business decision.

Agile & Scrum

Sprint
A fixed time-box (usually 2 weeks) in which a team delivers a working increment of software.
User Story
A requirement written from the user's perspective: "As a [user], I want [feature] so that [benefit]."
Acceptance Criteria
The conditions a user story must meet to be considered complete — QA's test checklist.
Sprint Planning
Meeting where the team selects and commits to work for the upcoming sprint.
Daily Standup
15-min daily sync: what did I do yesterday, what will I do today, any blockers?
Sprint Review
Demo of completed work to stakeholders at end of sprint.
Retrospective
Team reflects on what went well, what didn't, and what to improve next sprint.
Definition of Done (DoD)
Agreed checklist — what "done" means for every story (includes QA sign-off).

API Testing

API
Application Programming Interface — a contract between software components. REST APIs send/receive data via HTTP.
GET
HTTP method to retrieve data. Should never change data on the server.
POST
HTTP method to create new data.
PUT / PATCH
Update existing data. PUT replaces fully; PATCH updates partially.
DELETE
HTTP method to delete data.
200 OK
Request succeeded.
201 Created
Resource successfully created (POST).
400 Bad Request
The request was malformed — client error.
401 Unauthorized
Authentication required or failed.
403 Forbidden
Authenticated but not permitted to access this resource.
404 Not Found
The requested resource does not exist.
500 Internal Server Error
The server crashed or encountered an unexpected error.
