3. Positive vs Negative Testing — The 30/70 Rule

Every feature needs both types. A common junior QA mistake is writing only positive tests.

TypeTests what?Example for Registration
Positive
(Happy Path)		 The feature works correctly when given valid inputs Register with a valid email and a password that meets all requirements → account created
Negative
(Sad Path)		 The system handles invalid inputs and errors gracefully Register with an already-used email → clear error message shown, no duplicate account created
The 30/70 Rule

Aim for roughly 30% positive tests, 70% negative tests. The happy path is the one path developers tested themselves. Bugs live in the edges — invalid inputs, empty fields, unexpected sequences. That's where QA adds the most value.

Healthcare Parallel

In healthcare, you don't just check that the medication works for a typical adult patient. You check what happens for a patient with allergies, an elderly patient on other medications, a patient who refuses the dose, a patient who double-doses. The "normal" case is easy — the edge cases protect people.

4. Example: Two Test Cases for Registration

Here is what a professional test case looks like for OJS-4. Study these before writing your own.

TC_REG_001 Positive
Title
Verify successful registration with valid email, password, and security question
User Story
OJS-4
Priority
High
Preconditions
Juice Shop is accessible at http://192.168.0.202:9058. The email testuser1@qa.com is not already registered.
Test Data
Email: testuser1@qa.com  |  Password: Test@1234  |  Security Q: "Your eldest sibling's middle name?"  |  Answer: Priya
Steps
  1. Navigate to http://192.168.0.202:9058/#/register
  2. Enter testuser1@qa.com in the Email field
  3. Enter Test@1234 in the Password field
  4. Enter Test@1234 in the Repeat Password field
  5. Select "Your eldest sibling's middle name?" from the Security Question dropdown
  6. Enter Priya in the Security Answer field
  7. Click the "Register" button
Expected Result
User is redirected to the Login page. A success message is displayed confirming registration. No error messages appear.
TC_REG_003 Negative
Title
Verify error message when registering with an already-registered email address
User Story
OJS-4
Priority
High
Preconditions
Juice Shop is accessible. The email admin@juice-sh.op is already registered in the system.
Test Data
Email: admin@juice-sh.op  |  Password: Test@1234
Steps
  1. Navigate to http://192.168.0.202:9058/#/register
  2. Enter admin@juice-sh.op in the Email field
  3. Enter Test@1234 in the Password and Repeat Password fields
  4. Select any security question and enter any answer
  5. Click the "Register" button
Expected Result
Registration fails. An error message is displayed stating the email is already in use. No duplicate account is created.

5. How to Enter Test Cases in YouTrack Test Manager

Go to Test Manager

Log into YouTrack → click Test Manager in the left sidebar → select OWASP Juice Shop repository → click All test cases.

Create a Test Suite first

Click All test suites → New test suite → name it OJS-4 Registration. A test suite groups related test cases — like a folder.

Create your first test case

Click New test case (top right). In the form that opens, enter the Summary (title). Look for a Steps section — add each step with its expected result inline, or use the description field for the full template.

Link to the user story

In the test case, look for a Related issues or Links field. Link it to OJS-4. This is traceability — it proves your test covers that requirement.

Save and repeat

Save your first test case. Then repeat for each test case below. It gets faster each time.

YouTrack Tip

If YouTrack's Test Manager doesn't have all the fields you expect, use the Description field to paste your full test case in the template format. What matters is that the steps and expected result are clear — the exact fields are tool-dependent.
